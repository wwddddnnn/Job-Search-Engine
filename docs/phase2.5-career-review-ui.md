# Phase 2.5 人工整理与核验 UI

状态：需求已讨论确认，待实现。更新日期：2026-09-17。

本文记录用户确认的产品行为；实现切片是建议顺序，不表示功能已经交付。

## 目标与范围

用户在项目配置好的 Python 3.12 Conda 环境中运行启动命令，在浏览器打开本地应用，亲自导入、整理、编辑、核验并发布职业档案。交付必须可实际操作和人工验收。

首版支持多份 `.md` 简历。用户以手工整理为默认方式，将不同简历中的经历汇总到同一份个人职业档案。职业档案应容纳全部经历，供后续按目标职位生成不同简历；本阶段不实现简历生成。

本阶段包含：本地 Web UI 与必要的 HTTP/application service 契约、审核草稿持久化、自动保存、部分发布、多套 LLM API 配置、带引用的优化/合并操作入口，以及明确标识的 Mock 调用与结果应用。

本阶段不要求完成 PDF/DOC/DOCX 导入、真实 LLM 网络调用、自动简历抽取、Matching、Application、Agent/MCP。真实 LLM 调用仍属于后续 B 步；不能把“配置入口可用”表述为“真实调用已接入”。

## 页面与基本流程

1. 启动本地应用，选择中文或英文界面。简历和用户内容保留原始语言，不因切换界面语言而自动翻译。
2. 导入 `.md` 简历，可切换查看多份已导入文档。
3. 左侧默认显示排版后的 Markdown，并可切换源码；右侧编辑经历、成果和技能。
4. 鼠标选中原文后，可“新建经历”“添加成果”“添加技能”；也可以不选原文，直接手工填写。
5. 用户可以编辑、确认、拒绝或标记待澄清。确认经历不自动确认所有成果和技能。
6. 整理内容与核验进度自动保存，关闭页面或重启后可继续。
7. “发布档案”是单独的明确确认操作，发布前展示本次内容与变更摘要。
8. 发布后可查看职业档案及历史版本，并继续整理剩余草稿。

界面不提供“关联为证据”按钮，不要求用户手工维护证据关系。用户觉得描述不合适时，直接修改内容。

## 草稿、来源与版本

- 编辑内容独立保存为审核草稿，不能覆盖原始 Markdown 或历史抽取输出。手工整理不依赖成功的 LLM 抽取运行。
- 从原文创建条目时，后台自动保留文档引用和原文位置；修改时保留原文及修改记录。来源引用用于追溯，不等于修改后的表述已经被原文支持。
- 无文档依据的新增事实，在用户明确确认后以 `user_assertion` 保存，不伪装成简历事实。证据链仍由后端维护，不增加手工关联步骤。
- 删除整理中的条目支持撤销；删除已发布条目只影响下一版，历史版本仍保留。发布摘要需明确列出删除。
- 支持部分发布：只发布用户明确确认的新增或修改，其余内容继续保留在草稿。已有且未修改的已发布经历默认保留。
- 对已有条目的未确认修改，不应在部分发布时导致旧版已确认事实消失。用户明确确认删除后，才在新版本移除。
- 自动保存、Mock/LLM 输出、一键替换和自动合并均不自动将事实设为 verified。修改已确认内容后，需要重新确认修改后的内容。
- 发布应基于明确的档案基础版本，检查版本冲突，避免旧页面覆盖后来发布的内容。
- 没有已发布档案时展示可继续操作的空状态，不能将其混同于数据损坏；合法空档案与基础设施错误应有不同界面文案。

## 多份简历与重复经历

多份简历共同补充一份职业档案。导入新简历不会覆盖已有经历。

默认由用户选择新建经历，或将新内容添加到已有经历，再选择补充或替换字段；不自动合并重复经历。

用户也可显式选择“LLM 协助合并”，指定参与合并的内容。调用完成且输出通过校验后，自动将合并结果写入编辑草稿，不再要求逐字段采纳；保留合并前内容并支持撤销。合并不修改原始简历或历史档案，发布仍需单独确认。

Phase 2.5 用 Mock 接口演练合并流程；真实 LLM 合并由 B 步接入。输出无效、调用失败或目标草稿在等待期间已修改时，不得静默覆盖现有编辑。

## 自动保存与撤销

自动保存覆盖整理内容、审核决定、LLM 引用、用户 prompt 和配置选择；重启后能够恢复。

界面至少区分“未保存/待保存”“保存中”“已保存”“保存失败”，已保存只能在后端确认持久化成功后显示。失败时保留当前输入，并允许重试。防止旧保存请求覆盖新编辑。

发布必须使用已保存且与用户当前所见一致的草稿版本。撤销删除、替换或合并时，恢复相应编辑内容并继续自动保存；不能删除历史发布记录或修改原始输入。

## LLM API 配置

用户可添加、修改、删除多套配置，并在优化/合并面板中切换。首版按 OpenAI 兼容接口设计，其他接口后续扩展。

每套配置包含：名称、API 地址、API Key、模型名。

- API Key 保存在本机，应用重启后可继续使用；已保存的 Key 在界面中只显示掩码。
- Key 通过后端受控的本地秘密存储管理，不放入浏览器持久化存储、普通日志、审计正文或 Mock fixture。具体存储实现需在编码设计时明确；显示掩码不等于存储加密。
- 修改普通字段不应误把掩码当成新 Key；删除配置时同时处理其保存的凭据。
- 读取配置仅返回非秘密字段及是否已设置 Key 等状态。审计记录配置变更动作，不记录 Key 内容。
- 本阶段配置保存不触发真实请求，也不声称已经验证连通性。

## 带引用的优化交互

用户可从左侧简历原文、右侧编辑字段中用鼠标选取一句或一段文字，也可引用整个经历/成果。

选择“用 LLM 优化”后，侧栏显示引用内容及其来源，用户填写自己的 prompt 并选择 API 配置。请求上下文应保留选区/条目的稳定标识及版本，以确定结果应应用到哪里。

结果区分别展示优化建议和改写结果。优化结果由用户点击“一键替换”后应用：

- 引用右侧字段选区：替换原选区；引用整条经历/成果：应用到对应条目。
- 引用左侧原文：用户选择右侧目标字段或新建条目，原始 Markdown 不变。
- 保存替换前内容，支持撤销；替换只影响编辑草稿，不直接发布。
- 结果返回前目标已变化时，应提示用户重新选择/核对目标，不能按过期位置覆盖新内容。

这与“LLM 协助合并”不同：优化需要点击采纳，合并在用户显式启动后自动应用到草稿；两者均可撤销且仍需发布确认。

## Mock 与真实调用边界

普通模式提供引用、prompt、配置和操作入口；真实生成能力明确显示“待接入”，不得静默返回假建议。

提供独立、明确标识的 Mock 模式，通过假接口响应检查加载、结果展示、一键替换、自动合并、撤销和错误状态。Mock 不需要真实 API Key，不发外部请求，建议和结果始终标明演练来源。

后续 B 步用真实 provider 实现替换 Mock 调用能力，继续复用引用、prompt、结果展示、应用草稿及确认发布契约。

## 实现边界与建议切片

沿用应用服务为统一入口的规则：UI/HTTP adapter 不直连数据库，也不直接调用 store 内部写接口。所有写操作携带 actor、correlation ID 和幂等键；业务变更、审计和幂等完成状态保持一致。数据库变更新增迁移，不修改已应用迁移。

Phase 2 的确认接口仅支持抽取结果索引勾选；本阶段需要增加或扩展手工审核草稿、编辑、删除、部分发布及版本冲突的契约，不能让 UI 依赖现有 store 绕过这些服务。后台继续满足未确认事实不进入已发布档案/VerifiedEvidencePack 的约束。

延续现有依赖约定；本次讨论未批准新增第三方运行时依赖，也未选定前端框架。Markdown 渲染和源码视图须按不可信文档处理，不执行文档携带的脚本。

建议按以下顺序交付：

| 切片 | 内容 | 可人工检查的结果 |
|---|---|---|
| S1 | 审核草稿服务、来源保留、自动保存、部分发布与版本语义 | 通过测试验证重启恢复、未确认事实隔离和历史不可变 |
| S2 | 本地启动入口、HTTP adapter、中英文界面、Markdown 导入与双栏编辑 | 用户用自己的 `.md` 完成手工整理与发布 |
| S3 | 多配置管理、引用/prompt 面板、Mock 优化及一键替换 | 不需要 Key 即可演练结果应用与撤销 |
| S4 | 多文档补充已有经历、Mock 自动合并、完整人工验收说明 | 多份简历共同形成职业档案，可测试合并和撤销 |

## 验收标准

1. README 提供实际可执行的启动命令、本地访问地址和停止方法；使用项目既有 Conda 环境，不要求用户自行装配服务对象。
2. 用户可切换中英文界面，简历原文语言不变。
3. 可导入多份 `.md`，查看渲染/源码，选中文字创建条目，或直接手工添加；没有“关联为证据”操作。
4. 经历、成果、技能可编辑、核验和删除；整理与核验进度自动保存，保存状态准确，刷新/重启后恢复。
5. 部分发布生成新版本，保留未修改的旧事实及尚未发布的草稿；删除/修改不改变历史版本。
6. 手工补充和修改具备后台来源/修订记录，未确认内容不进入可信事实包。
7. 可新增、修改、删除多套 API 配置并切换；Key 本地保存、重启可用、界面掩码，日志与读取响应不泄露 Key。
8. Mock 模式支持选区/整条引用、自定义 prompt、建议与改写结果、一键替换及撤销；普通模式明确说明真实调用未接入。
9. 用户可手工处理重复经历；显式启动 Mock 合并会自动写入草稿，可撤销，仍需人工发布。
10. 测试覆盖自动保存顺序/失败、幂等重试、版本冲突、部分发布、旧结果覆盖防护及历史保留。自动测试不访问外部网络；本地 HTTP/浏览器验证可使用本机服务。
11. 提供独立演练数据与人工验收步骤，演练数据不冒充用户已确认的职业事实；本阶段不要求 PDF/DOC 或真实 LLM 调用通过验收。
